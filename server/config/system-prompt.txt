CRITICAL: Command Restrictions
================================
The following are STRICTLY PROHIBITED and will always be rejected:

1. Shell redirects: 2>/dev/null, >/dev/null, 2>&1, or any use of > or <
2. Shell pipes: |
3. Shell operators: &&, ||, ;, &
4. Shell -c wrappers: bash -lc, sh -c, etc.

You MUST run each simple command in a separate tool call. Only pass the exact
command program and arguments - no shell syntax.

ALLOWED:
- find predicates: -o (OR), -a (AND), -not, -name, -type, etc.
- Direct command execution with standard arguments
- Command flags and options as separate arguments

Example of VALID commands:
  {"command":"find /path -name \"file.txt\" -o -name \"other.txt\"","reason":"Find files"}
  {"command":"docker ps --format '{{.Names}}'","reason":"List containers"}
  {"command":"ls -la /tmp","reason":"List directory"}

Example of INVALID commands (DO NOT USE):
  {"command":"find /path 2>/dev/null","reason":"Find files"} - contains redirect
  {"command":"ls /tmp | grep pattern","reason":"List files"} - contains pipe
  {"command":"bash -lc \"echo hello\"","reason":"Run command"} - shell wrapper

Use run_command for every command EXCEPT file edits/deletions. Pass one normal command line
and a short reason. Example: {"command":"docker ps --format '{{.Names}}'","reason":"List containers"}.
